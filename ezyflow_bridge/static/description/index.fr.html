EzyFlow bridge

EzyFlow bridge est le module Odoo dont le connecteur EzyFlow a besoin, et rien d'autre : quelques champs, quelques comportements et une page de paramètres, pour qu'Odoo et le système de gestion d'entrepôt (le WMS) échangent transferts, stock, produits et commandes à travers EzyFlow. Le connecteur lui-même fonctionne hors d'Odoo. Les personnes qui le font fonctionner pour votre société sont l'équipe EzyFlow : elles vous transmettent les valeurs dont le connecteur a besoin, reçoivent les identifiants de ce que vous créez dans Odoo et voient les refus que décide le connecteur.

Cette page s'adresse à l'administrateur Odoo. Elle comporte deux parties. Configurer décrit ce que vous faites dans Odoo pour que le connecteur fonctionne. Utiliser décrit ce que les utilisateurs rencontrent sur les écrans d'Odoo une fois qu'il fonctionne, rédigé pour que vous le leur transmettiez. La même page est affichée ici depuis Apps et depuis le bloc Aide de la page de paramètres EzyFlow.

Configurer

1. Installer et mettre à niveau

Le module est publié dans un dépôt public sur GitHub, Ezytail/ezyflow-odoo-bridge. Chaque version du module est un tag de ce dépôt et une publication de sa page Releases, avec une archive zip de ce module, un fichier SHA256SUMS pour vérifier l'archive, et des notes de version. Le même module s'installe sur Odoo 19 et sur Odoo 20. Choisissez l'une des trois voies :

  • Une archive zip. Téléchargez l'archive de la version depuis la page Releases et décompressez-la dans un répertoire du chemin des modules d'Odoo (le dossier ezyflow_bridge se trouve à la racine de l'archive).
  • Un clone git. Clonez le dépôt, fixez-le sur le tag de la version, et placez la racine du dépôt dans le chemin des modules d'Odoo.
  • Odoo.sh. Ajoutez le dépôt comme sous-module de votre projet, sur la branche qui porte le nom de votre série, 19.0 ou 20.0.

Redémarrez ensuite Odoo, ouvrez Apps, choisissez Mettre à jour la liste des Apps et installez EzyFlow bridge.

Pour mettre à niveau, sauvegardez d'abord la base de données. Remplacez le dossier par celui de la nouvelle version (ou déplacez le clone sur le nouveau tag), puis lancez Odoo une fois avec -u ezyflow_bridge ou ouvrez le module dans Apps et appuyez sur Mettre à niveau. Redémarrez ensuite Odoo, pour que le code Python modifié soit chargé : le bouton Mettre à niveau lit les nouveaux fichiers mais ne redémarre pas Odoo. Les notes de chaque version indiquent si la mise à niveau est obligatoire ou facultative, si elle comporte une migration, si un redémarrage est nécessaire, et quoi vérifier ensuite. Lisez-les avant de mettre à niveau.

Trois versions comptent. La version installée est affichée dans Apps, sur le module. La plus ancienne version acceptée par le connecteur, et la version avec laquelle il a été construit, sont affichées dans le portail EzyFlow, et l'équipe EzyFlow vous les indique. La dernière version est la publication la plus récente de la page Releases. Un module plus ancien que la plus ancienne version acceptée par le connecteur est refusé : le connecteur ne fonctionne pas avec lui et l'indique dans le portail, en nommant la version installée et les deux autres. Un module d'une autre version majeure est refusé aussi. Un module plus récent que celui avec lequel le connecteur a été construit, dans la même version majeure, fonctionne : mettez d'abord le module à niveau, le connecteur suit.

Sur Odoo 20, un module installé en ligne de commande sur une base existante (-i ezyflow_bridge) est installé et fonctionne, mais reste masqué dans Apps jusqu'à la prochaine mise à niveau du module, qui répare son entrée. Installez depuis Apps quand vous le pouvez, ou lancez une fois -u ezyflow_bridge après une installation en ligne de commande.

2. L'utilisateur connecteur et sa clé

Le connecteur se connecte à Odoo avec un utilisateur qui lui est propre. Créez un utilisateur qui appartient à la société que sert le connecteur, donnez-lui le groupe Connecteur EzyFlow et aucun autre droit : le groupe porte déjà tout ce dont le connecteur a besoin, et chaque droit ajouté élargit ce que permettrait une clé divulguée. Ne lui donnez aucun rôle de vente, d'achat ou d'administration. Le connecteur s'adresse toujours à Odoo en anglais, quelle que soit la langue de l'utilisateur connecteur : les refus que lit l'équipe EzyFlow sont donc en anglais.

Donnez ensuite une clé API à cet utilisateur. Connecté en tant qu'utilisateur connecteur, ouvrez ses Préférences, l'onglet Sécurité, et appuyez sur Ajouter une clé API. Donnez à la clé une date d'expiration : le groupe autorise jusqu'à dix ans. Sur Odoo 20, laissez la Portée sur RPC, la valeur par défaut de l'écran. Odoo n'affiche la clé qu'une fois : transmettez-la à l'équipe EzyFlow par le canal qu'elle vous indique, jamais en clair par e-mail, et notez sa date d'expiration là où quelqu'un la verra avant qu'elle n'arrive.

Pour renouveler la clé, ajoutez une nouvelle clé sur le même utilisateur, transmettez-la à l'équipe EzyFlow et supprimez l'ancienne une fois qu'elle confirme que le connecteur fonctionne avec la nouvelle. Le connecteur prend la nouvelle clé en compte en moins d'une minute.

Quand la clé expire ou est supprimée, Odoo refuse le connecteur et l'équipe EzyFlow le voit comme une alarme de son côté : après quelques refus, le connecteur suspend son travail pour votre Odoo et le reprend de lui-même dès qu'une clé valide est en place. Quand un droit manque sur un type d'enregistrement, l'équipe EzyFlow voit un refus qui nomme cet enregistrement ; vérifiez que l'utilisateur a toujours le groupe Connecteur EzyFlow, qu'il est actif et qu'il appartient toujours à la société. Rien dans Odoo n'affiche ces refus : l'équipe EzyFlow vous les signale.

3. La page de paramètres EzyFlow

Ouvrez Paramètres et choisissez EzyFlow dans le menu de gauche. C'est le seul endroit où le module se configure ; les Paramètres système ne le sont pas. La page modifie la société sélectionnée dans la barre supérieure : ce qui est dit ci-dessous être par société se règle donc une fois pour chaque société que sert le connecteur. Les trois clés du bloc Connecteur valent pour toute la base et s'affichent quelle que soit la société sélectionnée.

Connecteur. Trois valeurs que vous transmet l'équipe EzyFlow, un seul jeu pour toute la base : Activité, URL de réveil et Secret de réveil. Grâce à elles, Odoo réveille le connecteur dès qu'un transfert est prêt pour lui au lieu d'attendre la prochaine interrogation. Enregistrer la page sans toucher au secret le conserve. Vider le secret et enregistrer l'efface : le connecteur refuse alors tout réveil et ne lit Odoo qu'à son intervalle, ce qui coûte du délai, jamais des données.

Contraintes WMS. Un interrupteur par règle et par société, tous activés à l'installation du module. Quand un interrupteur est activé, une personne qui enregistre ou confirme un enregistrement que le WMS refuserait plus tard est refusée immédiatement, avec un message qui nomme l'enregistrement, le champ et la limite. Les limites sont celles du WMS qu'EzyFlow sert pour vous ; une société sur un autre WMS désactive ce dont elle n'a pas besoin. Les interrupteurs ne s'appliquent qu'aux personnes : ce que le connecteur écrit depuis une boutique arrive tel que la boutique l'a envoyé, et le WMS en juge en chemin vers l'entrepôt.

Chaque limite est vérifiée quand son propre champ est écrit : un enregistrement qui dépasse déjà une limite est refusé la prochaine fois que quelqu'un modifie ce champ, pas avant.

Stock. Appliquer les rapports de stock, par société, désactivé à l'installation du module. Le WMS envoie un rapport de ce qu'il détient pour chaque produit. Désactivé, le connecteur écrit chaque quantité du rapport comme un comptage en attente qu'une personne vérifie et applique depuis Inventaire physique, et Odoo n'annonce rien aux boutiques pour ce rapport. Activé, les quantités sont appliquées immédiatement aux quantités en stock, sauf si l'équipe EzyFlow a désactivé l'application de son côté pour votre société. Les mouvements WMS, une réception ou une expédition enregistrée par le WMS hors d'un document Odoo, sont toujours appliqués, quel que soit l'interrupteur.

Documents. Rapport proforma, par société : le rapport de commande client que le connecteur génère comme proforma des commandes de la société et transmet au WMS pour les documents d'expédition. La liste ne propose que des rapports de commande client. Laissé vide, le connecteur génère la facture pro forma d'Odoo.

4. Types d'opération que sert le WMS

Ouvrez Inventaire, Configuration, Types d'opérations. Chaque type de réception et de livraison porte un Mode logistique qui indique si ses transferts vont au WMS : Automatique : proposé dès la réservation transmet un transfert dès qu'Odoo réserve son stock, Manuel : proposé quand une personne le décide attend que quelqu'un appuie sur Proposer à la logistique sur le transfert, et Désactivé : jamais proposé garde le type dans Odoo. Les transferts internes ne sont jamais proposés, quel que soit le mode. Le champ Canaux autorisés à côté nomme les canaux de vente que le type propose, sous forme de codes séparés par des virgules ; vide, il propose tous les canaux. Un même entrepôt peut ainsi servir le WMS pour son canal web et garder ses ventes au comptoir dans Odoo.

Les lots et numéros de série circulent dans les deux sens avec le WMS : le connecteur les écrit sur les livraisons et sur les réceptions qu'il enregistre. Laissez Créer nouveau et Utiliser les existants activés, comme Odoo les livre, sur les types de réception et de retour que sert le WMS, et laissez tels quels les réglages des types de livraison. Un produit suivi que le WMS reçoit sans lot donne une réception refusée : le WMS envoie les lots, ou le suivi du produit est désactivé.

5. Ce que la publication nomme par identifiant

L'équipe EzyFlow décrit votre Odoo au connecteur dans une publication, qui nomme plusieurs de vos enregistrements par leur identifiant en base. Vous les créez, puis transmettez chaque identifiant à l'équipe EzyFlow ; le connecteur les vérifie à son démarrage et refuse de fonctionner tant que chacun n'est pas tel que décrit. L'identifiant se lit dans la barre d'adresse du navigateur quand l'enregistrement est ouvert, ou en mode développeur sous Afficher les métadonnées.

  • Devises. Chaque devise dans laquelle une boutique vend, active, avec un fournisseur de taux ou des taux tenus à la main dans les paramètres de Comptabilité ou de Facturation. Une commande de boutique est enregistrée dans la devise dans laquelle le client a payé, ses montants écrits tels que la boutique les a encaissés ; les écarts de change par rapport au taux d'Odoo relèvent de la comptabilité, pas du connecteur.
  • Listes de prix. Une liste de prix par devise, et une par devise et par canal là où vous tarifez les canaux séparément, de la société ou partagée. La publication nomme chacune avec sa devise et son canal ; la liste donne sa devise à la commande et rien d'autre. Une liste dont la devise n'est pas celle que la publication indique pour elle bloque le connecteur jusqu'à ce que l'une des deux soit corrigée. Gardez la liste de prix par défaut de la société dans la devise de la société, et n'attribuez pas à un client une liste de prix dans une autre devise : Odoo donnerait aux commandes de boutique de ce client une devise que la publication n'attend pas.
  • Droits de douane et frais d'importation. Deux produits de type service, l'un pour les droits de douane et l'autre pour les frais d'importation qu'une boutique encaisse au paiement pour une vente livrée droits acquittés, avec le compte de produits et les taxes que souhaite la comptabilité. Ils arrivent comme des lignes ordinaires de la commande. Un produit qui n'est pas un service, ou qui est archivé, bloque le connecteur.
  • Position fiscale. Là où la société est immatriculée à la TVA dans un pays de destination, une position fiscale pour ce pays avec son numéro de TVA étranger et sa correspondance de taxes, appliquée automatiquement selon le pays. Le devis, la proforma et la facture impriment alors le numéro de TVA de la position à la place de celui de la société.

6. Données douanières des produits

Une livraison vers un autre pays, et une commande de boutique destinée à l'étranger, déclarent ce qu'Odoo connaît des marchandises : le Code SH et l'Origine des marchandises du produit, champs propres à Odoo sur la fiche produit. Rien n'est renseigné par défaut. Une livraison ou une commande de boutique à destination de l'étranger dont les marchandises n'ont pas l'un des deux est refusée par le connecteur, qui nomme les produits ; l'équipe EzyFlow voit le refus, Odoo non. Renseignez les deux champs sur chaque produit susceptible de passer une frontière ; un kit est déclaré par ses composants, ce sont donc les composants qui les portent.

7. Deux sociétés sur une même base

Le connecteur sert chaque société par une publication qui lui est propre, dont l'utilisateur connecteur appartient à cette société. Sur la page de paramètres EzyFlow, changez de société dans la barre supérieure pour régler les contraintes WMS de cette société, son interrupteur Appliquer les rapports de stock et son Rapport proforma. Les trois clés du bloc Connecteur sont partagées par toutes les sociétés de la base : elles se règlent donc une seule fois.

Utiliser

1. Les transferts et le WMS

Une réception ou une livraison d'un type d'opération en mode logistique est proposée au WMS : dès qu'Odoo réserve son stock en mode Automatique, quand quelqu'un appuie sur Proposer à la logistique dans l'en-tête du transfert en mode Manuel. Un transfert dont la case Bloqué est cochée n'est jamais proposé, quel que soit le mode, tant que la case n'est pas décochée.

L'État WMS, dans l'en-tête du transfert et en colonne de la liste des transferts, indique où en est le transfert dans sa remise au WMS. Odoo fixe la première valeur ; le WMS, par l'intermédiaire du connecteur, écrit les suivantes.

État WMS Signification
Prêt pour la logistiqueOdoo a proposé le transfert ; le connecteur ne l'a pas encore pris.
Envoyé à la logistiqueLe WMS l'a reçu.
Préparation à faireLe WMS l'a accepté et planifié.
Préparation en coursL'entrepôt est en train de le préparer ou de le réceptionner.
Préparation terminéeL'entrepôt a terminé ; les quantités sont connues.
Refusé par la logistiqueLe WMS l'a refusé ; le motif est connu de l'équipe EzyFlow.
Annulé par la logistiqueLe WMS l'a annulé.
ExpédiéLe colis a quitté l'entrepôt ; le transfert est validé.

Le menu Regrouper par de la liste des transferts propose État WMS : les transferts refusés et les transferts annulés se retrouvent ainsi dans des groupes à part.

D'Envoyé à la logistique à Annulé par la logistique, le transfert est entre les mains du WMS et un bandeau l'indique : Odoo ne le réserve ni ne le libère, et seul le connecteur peut modifier ses lignes (produits, quantités, lots). L'en-tête reste le vôtre : les dates, le contact, les notes et l'annulation. Annuler un transfert dans Odoo atteint le WMS, qui cesse d'y travailler.

Quand l'entrepôt expédie moins que ce que demandait le transfert, le connecteur valide le transfert pour ce qui a été expédié et Odoo crée un reliquat pour le reste, comme pour toute validation partielle ; le reliquat est proposé à son tour. Les lots et numéros de série que l'entrepôt a préparés ou reçus sont écrits par le connecteur sur les lignes du transfert : le transfert indique ainsi quel lot est parti chez quel client, et lequel est entré.

2. Commandes client venues d'une boutique

Une commande que le connecteur crée depuis une boutique porte, dans son onglet Autres informations, le Canal, un code tel que WEB ou PRO qui indique par quel canal de vente la commande est arrivée. Le canal est recopié sur le client quand le connecteur en crée un, et sur les transferts. Une personne qui saisit un canal doit saisir un code : lettres majuscules, chiffres, traits d'union et tirets bas, jusqu'à 32 caractères.

Le Statut de livraison de la commande affiche l'état WMS de ses transferts. Quand une commande a plusieurs transferts, Refusé par la logistique l'emporte, puis Annulé par la logistique, puis l'état du transfert que le WMS a touché en dernier. Le menu Regrouper par de la liste des commandes propose Statut de livraison.

Le Total boutique de l'onglet Autres informations est ce que le client a payé à la boutique, dans la devise de la commande. Quand Odoo calcule un autre total pour les mêmes lignes, un avertissement au-dessus de la commande indique les deux montants. La commande est maintenue et confirmée : vérifiez les taxes des lignes et la position fiscale du client, les deux éléments qui font différer le total d'Odoo de celui de la boutique. Les droits de douane et frais d'importation encaissés par la boutique apparaissent comme des lignes ordinaires sur les deux produits de type service nommés dans Configurer.

Un colis livré en point relais est adressé au point relais, un contact à part entière qui porte un Code relais ; le client qui le retire est le Destinataire final de la commande et du transfert. Le connecteur génère la proforma de la commande avec le Rapport proforma de la société et la transmet au WMS pour les documents d'expédition ; rien n'est joint à la commande pour autant.

Quand une personne confirme une commande à la main et que l'interrupteur Adresse de livraison : téléphone et e-mail obligatoires à la confirmation est activé, l'adresse de livraison doit avoir un téléphone et un e-mail, car le transporteur a besoin des deux : la confirmation est refusée tant qu'ils ne sont pas renseignés.

3. Produits

Les contraintes WMS de Configurer sont ce qu'une personne rencontre en enregistrant un produit : un message qui nomme le champ et la limite, pour la référence interne, le nom du produit et le code-barres. La référence interne est ce par quoi le WMS connaît un produit, un seul produit actif la détient donc : pour remplacer un produit, archivez d'abord l'ancien, puis le nouveau peut reprendre sa référence. Le code-barres est facultatif ; le WMS le scanne quand il y en a un. Le Code SH et l'Origine des marchandises sont nécessaires sur chaque produit susceptible d'être expédié à l'étranger, comme indiqué dans Configurer.

Un kit est un produit doté d'une nomenclature de type kit : le WMS connaît ses composants, jamais le kit, si bien qu'Odoo ne tient aucun stock sur un kit et n'affiche aucune quantité en stock pour lui. Sa disponibilité est calculée à partir de celle des composants. Les dimensions, les poids et les conditionnements appartiennent au WMS : ils y sont tenus, pas sur le produit Odoo.

4. Contacts

Les contraintes WMS d'un contact ou d'une adresse sont celles de Configurer : le nom, les lignes de rue, la ville, le code postal, le téléphone et l'e-mail ont chacun une limite, et le message la nomme. Un point relais est un contact comme un autre, créé par le connecteur avec un Code relais et un Transporteur relais ; laissez ces deux champs tels quels.

5. Inventaire

Le WMS compte le stock. Son rapport de ce qu'il détient arrive dans Odoo de l'une de deux façons, selon l'interrupteur Appliquer les rapports de stock de Configurer : appliqué aux quantités en stock, ou écrit en comptages en attente que quelqu'un vérifie et applique depuis Inventaire, Opérations, Inventaire physique. Un comptage en attente peut être appliqué sans risque juste après le rapport qui l'a écrit ; le rapport suivant redonne les quantités. Un mouvement WMS, une réception ou une expédition que l'entrepôt a enregistrée hors d'un document Odoo, est toujours appliqué, et efface le comptage en attente de l'emplacement qu'il touche.

Le WMS tient le stock des lots et numéros de série. Odoo enregistre sur les transferts quel lot est allé où, mais la quantité qu'Odoo affiche par lot n'est pas rapprochée de celle du WMS ; le chiffre fiable par produit est le total. La disponibilité d'un kit est republiée aux boutiques chaque fois que l'un de ses composants bouge ou que sa nomenclature change, entre deux rapports.

6. Qui a fait quoi

L'utilisateur connecteur ne laisse aucune ligne dans le fil de discussion, à dessein : un transfert que le WMS a fait passer par ses huit états porterait sinon un message par étape. Pour savoir si le connecteur ou une personne a touché un enregistrement en dernier, ouvrez ses métadonnées (mode développeur, Afficher les métadonnées) et lisez Mis à jour par. Les notes propres à Odoo apparaissent toujours : le silence couvre les écritures du connecteur, pas les messages d'Odoo.

7. Quand quelque chose semble anormal

Avant d'appeler l'équipe EzyFlow, relevez dans Odoo : la référence du transfert ou de la commande, son État WMS ou son Statut de livraison, et l'heure de sa dernière écriture (Mis à jour le dans les métadonnées). Transmettez-lui ces trois éléments ; elle retrouve l'échange correspondant de son côté. Un transfert qui reste en Prêt pour la logistique plus longtemps qu'une interrogation signifie que le connecteur n'a pas lu Odoo : vérifiez que l'utilisateur connecteur est actif et que sa clé n'a pas expiré, puis interrogez l'équipe EzyFlow.

Un refus que décide le connecteur est visible par l'équipe EzyFlow, pas dans Odoo : un produit suivi reçu sans lot, un produit expédié à l'étranger sans données douanières, un canal qui n'est pas un code, une commande dans une devise qu'aucune liste de prix ne sert. Le transfert ou la commande n'en porte aucune trace. Quand l'équipe EzyFlow signale un tel refus, la correction se fait dans Odoo ou dans la boutique, et la prochaine modification de l'enregistrement est relue.

Ce qui a changé entre deux versions du module, et où est passé un interrupteur, se trouve dans le CHANGELOG du module, livré à côté de cette page.
